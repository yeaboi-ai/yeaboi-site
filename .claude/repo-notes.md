# repo-notes — yeaboi-site

The facts `/ship` and `/sync-main` do not hardcode. Keep this short; anything longer than a page is
a skill, not a note.

## What this repo is

yeaboi.ai. Hand-written flat HTML, no build step, no framework, no deploy job — **GitHub Pages
serves this repo's root off `main`, so merging is publishing.** There is nothing between a merged PR
and production except this repo's CI.

`index.html` and `404.html` are the landing and error pages; `docs/` is the documentation subtree;
`assets/` holds the CSS, JS and brand art the whole site loads. `install.sh` is served at
`yeaboi.ai/install.sh` and is what `curl -LsSf https://yeaboi.ai/install.sh | sh` runs.

## Gate

`make ship-gate` = `lint` → `format-check` → `test` → `contracts-check` → `tooling-check`.

**`make site-seo` before you commit any page change.** The `<head>` block, the crawlable footer, the
`?v=` cache-bust, `sitemap.xml` and `robots.txt` are all generated by `scripts/gen_site_seo.py`, and
the test suite fails page by page when the committed HTML is stale. Adding a page also needs a
`KINDS` entry in that script and an entry in `NAV_GROUPS` in `assets/site.js` — the parity test names
whichever one you forgot.

`make site-og` re-renders the Open Graph card. It needs the `art` extra (Pillow + matplotlib) and is
only run when the brand art or the tagline changes.

## The upstream contract

`contracts/site.json` is **vendored, never edited here.** It carries what this site asserts about the
package — the Python floor in the structured data, the repo URL in the JSON-LD `codeRepository`, the
PyPI install target — and it comes from the `yeaboi` repo, pinned by sha in `.contracts-rev`.

To change one of those facts: change it in `yeaboi`'s `pyproject.toml`, run `make site-contract`
there, merge, then here run `make contracts-sync && make site-seo` and commit both. `contracts-check`
fails on an edited-in-place copy and prints a note when the pin is merely behind.

## Artefacts produced by the yeaboi repo

`graph.png` (the agent graph) and `demo.cast.gz` + `demo.gif` (the terminal demo) are generated over
in `yeaboi`, by scripts that have to import it, and written into a checkout of this repo. `assets/`
also holds the master duck art that `yeaboi`'s sprite and icon generators read. None of that is on
any PR's path — it moves when the product or the brand does. See `yeaboi`'s CLAUDE.md.

## After the push

Nothing rewrites the branch. A later push is a plain `git push`.

## Conflict playbook

| Path | Resolution |
|---|---|
| `**/*.html`, `sitemap.xml`, `robots.txt` | Generated. Take either side, then `make site-seo` and commit the result. |
| `assets/site.js` (`NAV_GROUPS`) | Hand-written and read by the generator. Merge by hand, then `make site-seo`. |
| `contracts/site.json` | Never hand-merge. Take either side, then `make contracts-sync`. |
| `.tooling-rev`, `.contracts-rev` | Take the newer sha, then run the matching `*-check`. |

## Unattended lane

None — every PR here is hand-shipped, so the `pr-feedback` review is advisory.
